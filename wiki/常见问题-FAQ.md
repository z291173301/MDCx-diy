# 常见问题 FAQ

按出现频率排序。问题没解决？欢迎[提议题](https://github.com/cdlongbow/mdcx-diy/issues/new/choose)。

---

## 1. 刮削失败？网络问题占大多数，怎么排查

**排查顺序**：

1. 左侧导航「**检测网络**」页 → 点「开始检测」→ 全量检测所有站点
2. 全红 → 检查代理（见下条）；个别红 → 该站点暂时不可用，属正常
3. 「检测进度」显示 `done/total`，耐心等检测完，**个别站点失败不会中断整轮检测**

**为什么很多站点需要代理**：多数元数据站点部署在海外或对国内 IP 有 Cloudflare 防护。默认「走代理网站」列表已覆盖 javbus/javdb/missav 等 34 个域名，需在本机先跑好代理软件（Clash/v2ray 等），程序默认读 `http://127.0.0.1:7890`。

## 2. 代理只能用 127.0.0.1 吗？（议题 #70）

不是。代理地址支持任意 HTTP/HTTPS/SOCKS5 地址，包括：

- 本地代理：`http://127.0.0.1:7890`、`socks5://127.0.0.1:1080`
- 局域网代理：`http://192.168.1.100:7890`（路由器/NAS 上的代理）
- 远程服务器：`http://your-server:port`

在「软件设置 → 网络 → 代理地址」填写即可。

补充（议题 #83）：「走代理网站」列表支持两种写法——填**域名**（javbus.com）只对该域名生效；填**数据源名**（missav、javdb、7mmtv，可从输入框旁下拉框直接选）则该站点的主域/镜像/备用域名全部自动走代理，站点换域名后无需改配置。旧版本曾存在"下拉框选了数据源名但部分站点仍直连"的问题，已在 2026-09 修复，建议升级。

## 3. 检测网络显示异常/某站点红了的含义

| 显示 | 含义 | 处理 |
|---|---|---|
| 连接正常，刮削正常 | 完全可用 | 无需处理 |
| 站点可达但测试番号未被收录 | 站点通，只是没收录该测试番号 | 忽略（见 #60） |
| 站点可达但被 Cloudflare 拦截 | 需配 CF Bypass 服务或换源 | 设置→网络→CF Bypass |
| 刮削探测 3 次均超时，判定该站刮削探测无效 | 站点能连上但刮削响应过慢（代理节点质量或站点负载） | 换代理节点/稍后再测；实际刮削仍可能成功 |
| 401/403/429 | 缺 Cookie / 被限流 | 补 Cookie（如 JavDb）或稍后再试 |
| 日本 IP 限定 | 需日本节点代理 | 站点列表有「日本IP限定」标注 |

**检测项单项失败不影响其他站点**，某个站挂了换其他源即可。

**v2.1.0 起刮削探测会自动递进重试**（议题 #115/#118）：同一站点首轮探测超时后立即再探第 2 次（45s）、第 3 次（60s），任一次通过即定论，三次都没过才判定该站探测无效，检测页会打印「↳ 站点 第 2/3 次刮削探测（超时上限 45s）」。只有超时/请求失败/探测异常这类瞬时结果才重试，「未被收录」「被 Cloudflare 拦截」首次即定论。「重试失败项」按钮用于改完代理/CF 配置后再验一次（同样走 30s/45s/60s 阶梯）。

## 4. 窗口最大化后内容布局乱/不跟随

v2.0.8 已全面修复：软件界面/软件工具/软件日志/检测网络的内容都会跟随窗口缩放；软件设置页全部 12 个 tab（刮削目录/刮削模式/刮削网站/下载/命名/翻译/字幕/水印/NFO/演员/网络/高级）也已同步修复——内容会拉满视口宽度、底部「当前配置/另存为/恢复默认/保存」浮框随窗口底部锚定、滚动到底末行不再被浮框遮挡。如仍遇到，请提议题并附截图（注明窗口模式：原生边框/隐藏边框）。

v2.1.0 另修复软件界面最大化后「封面/缩略图黑框盖住下方简介、标签、日期、导演、制作、厂牌、系列、发行等字段」的重影（议题 #124）：图片框会随窗口变宽而横向放大，下方字段此前仍停在原位被黑框压住。现字段区整体右移到缩略图框右缘之后、尺寸文字与勾选框跟随封面框底边，默认窗口尺寸下无变化。请升级或拉取最新代码重新打包后确认。


## 5. 界面文字重影/重叠（如「CF Bypass时…」）

v2.1.0 已修复网络设置页「CF Bypass 代理」与「超时时间」两行文字叠压的重影（议题 #123）：上一版新增「直连白名单」行后下方两行没有跟随下移，挤进同一行造成文字叠压。请升级或拉取最新代码重新打包，界面标签恢复正常后重影即消失。若其它页面也见类似文字重叠，请截图提议题（注明版本）。

## 6. 演员管理、信息管理入口可以隐藏吗？（议题 #61/#71）

可以。「软件设置 → 高级 → 隐藏入口」勾选后导航即时隐藏，功能本体保留，随时可重新开启。

## 7. 保存设置没生效 / 切换配置失败 / 卡死内存占满（议题 #55/#69）

v2.0.7 已修复三个根因：旧配置残留站点值导致校验失败、迁移警告被误判、网络栈轮询累积。如再遇到：

1. 备份 `userdata` 目录
2. 删除 `xxx_failed.json`（若出现）
3. 用默认配置重建，逐项导回

## 8. fanart.jpg 变成了 .fanart.jpg.xxx.tmp（议题 v2.0.8）

旧版在 Windows 上复制 fanart 时被杀软/索引瞬时占用导致失败但假报成功。v2.0.8 已三层修复（重试/真实报错/自动清理）。旧残留文件：内容其实是完整图片，**手动改名回 `fanart.jpg` 即可**，或删除后重刮。

## 9. 刮削到的封面有水印/画质差

优先调整站点优先级：JavDB 系（App 无水印通道）> DMM 高清 > 其他。设置 → 刮削网站 → 拖拽排序。详见主仓库 FEATURES.md「图源」章节。

## 10. 剧照下载失败 / 站点已删除剧照（议题 #131）

部分网站（如 JavDB、AVBase）的剧照由各自 CDN 托管，影片下架或图床清理后，即使能刮到剧照地址，下载也会 404 失败。v2.1.0 起会按「剧照」字段的来源优先级依次回退：某个网站整组剧照下载失败时自动尝试下一个剧照网站，全部失败才沿用本地旧文件。若经常遇到：

- 在「软件设置 → 刮削网站 → 字段优先级（剧照）」里把更稳定的来源（如 JavDB、DMM）排前；
- 勾选「图片下载失败时，不视为失败！」可避免个别剧照缺失导致整个文件被记为失败。

## 11. 软链接是什么？为什么我不能播放

软链接（类快捷方式）适合 PT 保种场景：原文件不动，目标目录放链接。注意很多播放器/媒体服务器**不能直接播放软链接**，仅适合海报墙展示。

## 12. 检测网络提示"自检固定四项"

启动时的自动自检只测基础连通（数据库 / ThePornDB / JavDb / JavBus / FC2PPVDB），**全量站点检测请到「检测网络」页手动触发**，这是设计如此。

## 13. 番号明明存在但刮不到（议题 #60）

- 先确认番号写法：`SSIS-742` 与 `SSIS742` 都可以，但系列字母不能错
- 用「检测网络」页可输入任意番号单测
- 部分站点收录不全属正常——多站点源会自动互补，个别站点失败不影响整体
- **看日志里 `[number]` 是不是整段文件名**：若番号识别失败，软件会把清洗后的整个文件名当番号去搜，站点必然「失败并跳过」（如 `T38-041__田舎に帰省した…` 这类单字母+两位数字厂牌带标题的文件名，2026-09-12 已修复）；把日志 `[number]` 行发出来即可快速定位

## 14. 同系列影片被分到不同文件夹（议题 #95）

目录名超过「最大长度」触发智能缩短时，**系列名（series）目录** 的截断长度以前取决于同批次其它字段（标题/演员/片商）的长短——同一系列的两部片子可能截出不同的系列目录名（差一个结尾字符），从而分家。

2026-09-12 起，模板里构成路径一级的字段（series/actor 等）改为按「稳定预算」截断：同一个系列名无论刮哪部片子都恒定截成同一个目录名，同系列必定归到同一文件夹。极长系列名会比以前多截几个字符，属预期代价。

## 15. JavDb 提示需要 Cookie

JavDb 网页版搜索 FC2 内容需要登录 Cookie。「软件设置 → 网络 → Cookie设置」里找到 JavDb 那一行，粘贴浏览器里的 Cookie 值；或改用 javdb_app/javdb_api 源（免 Cookie）。

## 16. 大模型翻译超时/失败

- 检查 API Key 有效、账户余额
- 网络代理是否放行 API 域名（多数 LLM 服务商国内直连或需特定代理）
- 系列片/失败重刮的同批文本有缓存，重试成本低

## 17. 补全演员信息时维基百科/Wikidata 请求失败或被限流

补全 Emby/Jellyfin 演员信息会查询维基百科与维基数据，这些站点对请求频率有严格限制（未识别请求仅 10 请求/分）。v2.1.0 起已把维基域名单独限速为 1 请求/秒，并使用带项目地址的可识别 User-Agent，归入 200 请求/分档，一般不再触发限流。若仍遇到：

- 多人共用同一出口 IP（公司/校园网、公共代理）时，可能被同 IP 的其他用户连累限流，换网络或稍后再试；
- 该演员在维基百科没有词条时属正常的「未收录」，可改用 minnano 或本地演员库来源补全。

## 18. 更新后旧配置还能用吗

能。配置自动迁移，已删除站点的旧值自动清理，新增站点（如 7mmtv）自动并入默认源。

## 19. TRAWL 便携版启动报 `Cannot find package 'elysia'`

这是 trawl-portable-1.5.0-windows.zip 启动脚本的缺陷（v1.5.0 包内脚本首次启动必然触发），两种解决方式任选：

- **免下载修复**：用主仓库 `scripts/windows/start-trawl.bat`（2026-09-11 之后）覆盖包内同名文件，直接重新双击启动——新版脚本直接运行包内自带源码与依赖，完全离线
- **临时应急**：在解压目录打开命令行执行 `cd src && ..\bun\bun.exe install`，装完再运行 `start-trawl.bat`

后续重新打包的便携版已内置修复脚本。

## 21. 关闭演员管理器后主程序一起退出（议题 #159/#175）

现象看起来一样，触发条件不同，请对号入座：

- **主窗口已经藏到托盘**，再关演员管理器（议题 #159，v2.1.1 修复）：Qt 默认「最后一个可见窗口关掉就退出」。主窗藏起来后，演员管理器成了最后一个可见窗，关掉它等于退出整个软件。修后关闭任何工具窗口都只关它自己；要退出请用主界面关闭按钮，或托盘菜单「退出 MDCx」。
- **正在获取数据时关演员管理器**（议题 #175，v2.1.1 修复）：空闲关闭大多没事；取数/同步/清洗中途关窗，会把还在跑的后台线程连窗口一起拆掉——Windows 上整进程直接中止，日志常是空的。修后关闭前会取消并等待这些线程，主程序保持运行。

请升级到含上述修复的版本后确认。若仍复现，请说明关窗时主窗是可见、最小化还是已藏托盘，以及演员管理器当时是否正在取数。

## 22. 演员管理器日志出现「wiki 个人资料表格列数不匹配」或「跳过 N 个不在所选媒体库影片中出演(Actor)的人员」（议题 #176/#157）

- **「表格列数不匹配」**：是解析 bug（v2.1.1 修复）。日文演员信息框模板的数据格带对齐样式，旧解析误把整表跳过，生日/出生地丢失——升级后这些页面可正常解析，无需手动干预。
- **「跳过 N 个…出演(Actor)的人员」**：预期行为。Emby 人物列表接口不支持按角色过滤（导演/编剧/配音会一并返回），软件与「所选库影片演职员表中角色=演员」的人名集合取交集剔除其余人员。若确认某人以「演员」身份出演于所选库影片仍被跳过，请提议题并附该人在 Emby 网页端的演职员分类截图。
